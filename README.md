# Equipment Maintenance Hub

A polyglot monorepo with an Angular 22 frontend, a FastAPI backend and one shared OpenAPI
contract. This README covers how the contract stays the **single source of truth** for both
languages:

1. **Runtime enum constants** in TypeScript and Python (`STATES`, `ACTIONS`, `PRIORITIES`).
2. **Compile-time checks** that keep those constants in sync with the generated types.
3. **A drift guard** (`npm run verify:contract`) that fails when committed generated code no
   longer matches `openapi.yaml`.

## Repository layout


## 1. The contract: enums in `openapi.yaml`

The three enums are defined once, in `packages/contract/openapi.yaml`:

```yaml
WorkOrderState:
  type: string
  enum: [reported, triaged, scheduled, in_progress, completed, cancelled]

WorkOrderAction:
  type: string
  enum: [triage, schedule, start, complete, cancel]

Priority:
  type: string
  enum: [low, medium, high, critical]
```

Two generators turn this file into code:

| Generator | Command | Output |
| --- | --- | --- |
| openapi-typescript | `npm run contract:generate:ts` | `packages/contract/src/types.gen.ts` |
| datamodel-code-generator | `npm run contract:generate:py` | `apps/backend/app/generated/contract_models.py` |

Each language gets different output from the same enum:

```ts
// types.gen.ts: a type only. It is erased at runtime, so you can't loop over it.
WorkOrderState: "reported" | "triaged" | "scheduled" | "in_progress" | "completed" | "cancelled";
```

```python
# contract_models.py: a real class that exists at runtime.
class WorkOrderState(StrEnum):
    reported = "reported"
    triaged = "triaged"
    ...
```

This difference is why the two languages need different solutions below.

## 2. TypeScript: runtime constants with a compile-time guard

File: `packages/contract/src/index.ts`

### The problem

A TypeScript union type is erased at compile time. To fill a dropdown or validate a query
parameter you need a real array. If you write one by hand, it can silently drift from the
contract.

### The solution

```ts
type Missing<Union, Values extends readonly unknown[]> = Exclude<Union, Values[number]>;

/** Identity at runtime; compile-time check that `values` lists exactly the members of `Union`. */
const enumValues =
  <Union extends string>() =>
  <const Values extends readonly Union[]>(
    values: Values &
      ([Missing<Union, Values>] extends [never]
        ? unknown
        : { readonly missing: Missing<Union, Values> }),
  ): Values =>
    Object.freeze(values);

export const STATES = enumValues<WorkOrderState>()([
  'reported',
  'triaged',
  'scheduled',
  'in_progress',
  'completed',
  'cancelled',
]);

export const ACTIONS = enumValues<WorkOrderAction>()([
  'triage',
  'schedule',
  'start',
  'complete',
  'cancel',
]);

export const PRIORITIES = enumValues<Priority>()(['low', 'medium', 'high', 'critical']);
```

### How it works, piece by piece

| Code | What it does |
| --- | --- |
| `Missing<Union, Values>` | `Values[number]` is the union of the array's elements. `Exclude` gives the union members the array **does not** contain. |
| `enumValues<Union>()` (outer call) | Fixes the target union, e.g. `WorkOrderState`. The function is curried because TypeScript can't take one explicit type argument and infer the other in the same call. |
| `<const Values extends readonly Union[]>` | **Check 1, assignability.** Each element must be a member of the generated union. The `const` modifier infers a literal tuple (`readonly ['reported', ...]`), not `string[]`. |
| `[Missing<...>] extends [never] ? unknown : { missing: ... }` | **Check 2, completeness.** If nothing is missing, the parameter type is `Values & unknown`, which is just `Values`. If something is missing, the argument must also have a `missing` property it can't have, so the call fails and the error message names the missing value. The brackets stop the conditional from distributing over the union. |
| `Object.freeze(values)` | The only runtime work: it makes the array immutable. The function returns its input, so the cost is effectively zero. |

### What the compiler reports when the contract changes

A value **added** to `openapi.yaml` (or removed from the array):

```
error TS2345: Argument of type '["reported", "triaged", "scheduled", "in_progress", "completed"]'
is not assignable to parameter of type '... & { readonly missing: "cancelled"; }'.
  Property 'missing' is missing in type '[...]' but required in type '{ readonly missing: "cancelled"; }'.
```

A value **removed or renamed** in `openapi.yaml` (or a typo in the array):

```
error TS2322: Type '"urgent"' is not assignable to type '"low" | "medium" | "high" | "critical"'.
```

### Usage

```ts
import { PRIORITIES, type Priority } from '@equipment-maintenance-hub/contract';

PRIORITIES.forEach((p) => console.log(p));    // runtime iteration
type P = (typeof PRIORITIES)[number];          // same as Priority
const isPriority = (v: string): v is Priority =>
  (PRIORITIES as readonly string[]).includes(v);
```

> The package's `exports` map in `packages/contract/package.json` has a `default` condition
> next to `types`. Without it, a bundler could resolve the types but not the runtime arrays.

## 3. Python: re-exports and immutable tuples

File: `apps/backend/app/contracts.py`

```python
from typing import Final

from app.generated.contract_models import (
    ApiError,
    Asset,
    AssignmentCommand,
    ByState,
    DashboardSummary,
    HealthStatus,
    NewWorkOrder,
    Priority,
    Technician,
    TransitionCommand,
    WorkOrder,
    WorkOrderAction,
    WorkOrderState,
)

STATES: Final[tuple[WorkOrderState, ...]] = tuple(WorkOrderState)
ACTIONS: Final[tuple[WorkOrderAction, ...]] = tuple(WorkOrderAction)
PRIORITIES: Final[tuple[Priority, ...]] = tuple(Priority)
```

### How it works

| Code | What it does |
| --- | --- |
| `from app.generated.contract_models import ...` | Re-exports the generated models **unchanged** (`contracts.WorkOrder is contract_models.WorkOrder`). Application code imports from `app.contracts`, so the generated module stays an internal detail. |
| `tuple(WorkOrderState)` | Iterating an `Enum` class yields its members in definition order, which is the order in `openapi.yaml`. The tuple is built from the generated enum, so it **can't** drift. No hand-written list is needed. |
| `tuple` | Immutable: `STATES.append(...)` or `STATES[0] = ...` raises an error. |
| `Final[...]` | Tells mypy the name can't be reassigned (`STATES = ()` elsewhere is a type error). |
| `StrEnum` members | Each member is also a `str`, so `contracts.PRIORITIES == ("low", "medium", "high", "critical")` is `True` and the values serialize to JSON as plain strings. |
| `__all__` | Declares the public API explicitly (sorted, as ruff's `RUF022` requires). |

### Usage

```python
from app.contracts import PRIORITIES, STATES, Priority, WorkOrder

for state in STATES:
    print(state.value)

assert Priority.high in PRIORITIES
assert "high" in PRIORITIES          # StrEnum compares equal to its string value
```

### Tests (`apps/backend/tests/test_contracts.py`)

```python
def test_models_are_re_exported_unchanged() -> None:
    for name in contracts.__all__:
        if name.isupper():            # skip STATES / ACTIONS / PRIORITIES
            continue
        assert getattr(contracts, name) is getattr(contract_models, name)


def test_every_generated_model_is_re_exported() -> None:
    generated = {
        name
        for name, value in vars(contract_models).items()
        if isinstance(value, type) and value.__module__ == contract_models.__name__
    }
    assert generated <= set(contracts.__all__)
```

- The first test checks that `contracts.py` never replaces a model with its own copy (`is`
  compares identity, not equality).
- The second test finds every class *defined in* the generated module (the `__module__` check
  skips imports such as `BaseModel`). It fails when a new schema added to the contract is
  not re-exported yet.
- Two more tests check that each tuple equals `tuple(enum)` and holds the expected strings in
  contract order.

## 4. The drift guard: `npm run verify:contract`

File: `scripts/verify-contract.mjs`, wired in the root `package.json`:

```json
"verify:contract": "node scripts/verify-contract.mjs",
"verify": "npm run verify:contract && npm run lint && npm run typecheck && npm run test && npm run build"
```

### The problem

The compile-time checks above compare the constants with the **generated** files. If someone
edits `openapi.yaml` and forgets to regenerate, the generated files are stale, and every check
still passes against the outdated types. The guard closes that gap.

### Step 1: describe each generator

```js
const generators = [
  {
    label: 'TypeScript (openapi-typescript)',
    committed: 'packages/contract/src/types.gen.ts',
    tmpParent: tmpdir(),
    generate: (tmp) => {
      const require = createRequire(join(contractDir, 'package.json'));
      const pkgPath = require.resolve('openapi-typescript/package.json');
      const pkg = JSON.parse(readFileSync(pkgPath, 'utf8'));
      const cli = join(dirname(pkgPath), pkg.bin['openapi-typescript'] ?? '');
      const output = join(tmp, 'types.gen.ts');
      run(process.execPath, [cli, 'openapi.yaml', '--output', output], contractDir);
      return output;
    },
  },
  {
    label: 'Python (datamodel-codegen)',
    committed: 'apps/backend/app/generated/contract_models.py',
    tmpParent: backendDir,
    generate: (tmp) => {
      const output = join(tmp, 'contract_models.py');
      run('uv', ['run', '--directory', backendDir, 'datamodel-codegen', '--output', output], backendDir);
      return output;
    },
  },
];
```

- Each entry runs the **same generator with the same settings** as `contract:generate:*`.
  Only `--output` changes, and it points to a temporary directory. The committed files are
  never overwritten.
- **TypeScript:** `createRequire(...)` finds the `openapi-typescript` CLI the way the contract
  workspace would, and the script runs it with the current Node binary (`process.execPath`).
  That avoids `npx` and shell quoting problems (the repo path contains spaces).
- **Python:** every option except `--output` comes from `[tool.datamodel-codegen]` in
  `apps/backend/pyproject.toml`, so the config lives in one place.
- **Why `tmpParent: backendDir`?** datamodel-codegen formats its output with ruff, and ruff
  reads its settings (e.g. `line-length = 100`) from the `pyproject.toml` nearest the output
  file. Under the OS temp folder, ruff would use its default of 88 and report drift that
  isn't real. So the Python temp directory is created inside `apps/backend`. The
  `.verify-contract-*/` pattern is in `.gitignore` in case a run is interrupted.

### Step 2: run commands safely

```js
function run(command, args, cwd) {
  const result = spawnSync(command, args, { cwd, stdio: ['ignore', 'pipe', 'pipe'], encoding: 'utf8' });
  if (result.error) throw result.error;
  if (result.status !== 0) {
    throw new Error(`\`${command} ${args.join(' ')}\` exited with ${String(result.status)}\n${result.stderr}`);
  }
}
```

`spawnSync` with an argument array (no shell) passes paths with spaces unchanged. A failing
generator raises an error that includes its stderr.

### Step 3: generate, compare, clean up

```js
for (const generator of generators) {
  const tmp = mkdtempSync(join(generator.tmpParent, '.verify-contract-'));
  let fresh;
  try {
    fresh = readFileSync(generator.generate(tmp));
  } catch (error) {
    failed = true;
    console.error(`verify:contract: ${generator.label} generation failed.`);
    console.error(error instanceof Error ? error.message : error);
    continue;
  } finally {
    rmSync(tmp, { recursive: true, force: true });
  }
  const committedPath = join(root, generator.committed);
  const committed = existsSync(committedPath) ? readFileSync(committedPath) : undefined;
  const ok = committed?.equals(fresh) ?? false;
  console.log(`  ${ok ? 'ok   ' : 'STALE'}  ${generator.committed}`);
  if (!ok) stale.push(`${generator.committed}  (${generator.label}${committed ? '' : ', file missing'})`);
}
```

- `mkdtempSync` creates a unique directory for each run, so parallel runs don't collide.
- `finally { rmSync(...) }` removes the temp directory on success **and** on failure.
- `Buffer.equals` compares **byte for byte**. Whitespace, line endings or a hand edit to a
  generated file all count as drift.
- A missing committed file counts as stale (`committed?.equals(...) ?? false`).
- Both generators always run, so one run reports every stale file.

### Step 4: exit code and message

```js
if (failed) process.exit(1);

if (stale.length > 0) {
  console.error('\nverify:contract: FAILED. Committed generated files differ from packages/contract/openapi.yaml:');
  for (const line of stale) console.error(`  - ${line}`);
  console.error('\nRun `npm run contract:generate`, review the diff, and commit the result.');
  console.error('Never edit generated files by hand.');
  process.exit(1);
}
```

A non-zero exit code fails `npm run verify` and any CI step that runs it.

## 5. Demo: breaking the contract on purpose

**Clean tree:**

```
$ npm run verify:contract
  ok     packages/contract/src/types.gen.ts
  ok     apps/backend/app/generated/contract_models.py

verify:contract: generated TypeScript and Python models match openapi.yaml.
```

**Add a value to the `Priority` enum in `openapi.yaml` and don't regenerate:**

```diff
 Priority:
   type: string
-  enum: [low, medium, high, critical]
+  enum: [low, medium, high, critical, urgent]
```

```
$ npm run verify:contract
  STALE  packages/contract/src/types.gen.ts
  STALE  apps/backend/app/generated/contract_models.py

verify:contract: FAILED. Committed generated files differ from packages/contract/openapi.yaml:
  - packages/contract/src/types.gen.ts  (TypeScript (openapi-typescript))
  - apps/backend/app/generated/contract_models.py  (Python (datamodel-codegen))

Run `npm run contract:generate`, review the diff, and commit the result.
Never edit generated files by hand.
$ echo $?
1
```

**Fixing it shows all the layers working together:**

1. `npm run contract:generate`: both generated files now include `urgent`, so
   `verify:contract` passes.
2. `npm run typecheck`: **fails**, because `PRIORITIES` in `index.ts` does not list the new
   member (`{ readonly missing: "urgent" }`). Add `'urgent'` to the array.
3. Python needs no change: `tuple(Priority)` picks up `Priority.urgent` automatically. Only
   the test that pins the exact strings (`test_tuples_hold_the_contract_strings`) needs
   updating, which is intended: a contract change should be a visible, reviewed change.

## Summary of guarantees

| Scenario | Caught by |
| --- | --- |
| `openapi.yaml` edited, generators not run | `npm run verify:contract` |
| Generated file edited by hand | `npm run verify:contract` |
| Contract gains an enum value, TS array not updated | `tsc` (`missing` error) |
| TS array contains a value the contract doesn't have | `tsc` (not assignable) |
| Python tuple out of sync with the contract | Not possible: built from the generated enum |
| Generated Python model not re-exported by `contracts.py` | `pytest` (`test_every_generated_model_is_re_exported`) |
